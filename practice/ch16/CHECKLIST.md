# 代理上線前檢查表（Agent Pre-Launch Checklist）

> K29《Building Agentic AI》第 16 章「從說話到行動（總結一）」演練。書 PDF 沒擷取到本章內容，以下依章名主題自行設計。
> 適用對象：會「呼叫工具、改變外部狀態」的 LLM 代理（不是只回文字的聊天機器人）。
> 標記方式：✅ 通過／❌ 未通過／N/A 不適用。每一項都要附**證據**（檔名＋行號、指令輸出或測試名稱），沒有證據就不算 ✅。

## A. 功能正確性

| ID | 檢查項目 | 怎麼驗證 |
| --- | --- | --- |
| A1 | 主要任務能端到端完成 | 離線模式（fake）跑一次＋真模型跑一次，確認迴圈收到 `final`、預期的工具都有被呼叫 |
| A2 | 每個工具都有單元測試（正常／邊界／錯誤） | 跑 `pytest`，對照測試清單：每個工具至少有 1 個正常、1 個邊界（空輸入）、1 個錯誤案例 |
| A3 | 代理的最終產出經過自動檢查 | 找有沒有測試或程式去比對「報告裡的數字」和「工具算出的數字」是否一致，不能只靠人眼看 |
| A4 | 有固定評估集，量得出成功率 | 找有沒有 ≥ 5 個任務、每個任務跑多次真模型的紀錄；只有一次成功不算 |
| A5 | 模型輸出格式有容錯 | 測試 code fence、前後雜訊、非 JSON 輸入時，解析器能抽出決策或明確報錯 |

## B. 工具與權限

| ID | 檢查項目 | 怎麼驗證 |
| --- | --- | --- |
| B1 | 工具清單最小化，且每個工具都有 schema | 列出所有工具，確認每個都是任務必要的，並有 name／description／input_schema |
| B2 | 工具參數經過驗證 | 傳錯型別、多餘參數、缺必填參數，確認都回傳錯誤而不是執行 |
| B3 | 檔案系統有沙盒 | 用 `../`、絕對路徑、`data/../x` 嘗試讀寫，確認全部被擋 |
| B4 | 輸入資料唯讀，讀寫權限分開 | 嘗試用寫入工具寫到輸入資料的位置（例：`data/sales.csv`），確認被擋 |
| B5 | 未知工具會被拒絕 | 讓模型呼叫不存在的工具（例：`rm_rf`），確認回傳錯誤、沒有執行任何東西 |

## C. 安全防護

| ID | 檢查項目 | 怎麼驗證 |
| --- | --- | --- |
| C1 | 機密不寫死、不外洩 | 搜尋程式碼有無 API key；檢查子程序的環境變數；確認沒設全域 `ANTHROPIC_API_KEY` |
| C2 | 有防 prompt injection | 在資料中放「忽略以上指示…」字樣，檢查 prompt 是否把外部資料標記為不可信、或做過濾 |
| C3 | 破壞性操作需要人工確認 | 讓代理覆寫既有檔案，確認會停下來詢問，或至少不會靜默覆寫 |
| C4 | 輸出內容檢查（PII、敏感資訊） | 若資料含個資，確認報告寫出前有遮罩或過濾 |
| C5 | 執行環境隔離 | 檢查子程序的 `cwd`、環境變數，確認不會讀到不相干的設定檔 |

## D. 成本與效能

| ID | 檢查項目 | 怎麼驗證 |
| --- | --- | --- |
| D1 | 有回合（步數）上限 | 用「永遠不回 final」的假模型，確認迴圈會在上限停下 |
| D2 | 有單次逾時與總時間上限 | 檢查每次模型呼叫有 timeout，且整個任務有總時限（算最壞情況：回合數 × 重試數 × 單次逾時） |
| D3 | 有成本計量與上限 | 確認每次呼叫的成本有被累加，超過上限會停 |
| D4 | prompt 大小有控制 | 確認歷史結果有截斷或摘要，大資料用參照傳遞而不是整包抄進 prompt |
| D5 | 模型版本固定 | 確認呼叫時指定了模型，不會因為 CLI 預設模型改變而行為漂移 |

## E. 可觀測性

| ID | 檢查項目 | 怎麼驗證 |
| --- | --- | --- |
| E1 | 每回合都有 trace | 跑一次後打開 trace，確認有每回合的工具、參數、結果摘要 |
| E2 | 失敗時也會寫出 trace | 讓模型呼叫中途丟例外，確認 trace 仍然寫出（`try/finally`） |
| E3 | trace 有時間戳、耗時、成本 | 檢查 trace 欄位 |
| E4 | 停止原因明確，exit code 可區分 | 正常完成、到達上限、出錯三種情況，各跑一次看 trace 欄位與 exit code |
| E5 | 大量／敏感內容不直接進 log | 檢查 trace 是否只存摘要（筆數、樣本、字數），不是全文 |

## F. 失敗處理與人工介入

| ID | 檢查項目 | 怎麼驗證 |
| --- | --- | --- |
| F1 | 工具錯誤會餵回模型，不讓代理崩潰 | 讓工具拋出預期中的錯誤，確認回傳 `{"error": ...}` 並繼續下一回合 |
| F2 | 非預期例外也會被攔截 | 製造 OSError（例：寫到目錄）、編碼錯誤，確認不會直接 traceback |
| F3 | 模型輸出解析失敗會重試 | 模擬第一次回垃圾、第二次回合法 JSON，確認成功並留下紀錄 |
| F4 | 上游服務失敗會重試／退避 | 模擬模型 CLI 或 API 回傳非 0，確認有重試，且有次數上限 |
| F5 | 有人工介入點，非互動環境預設拒絕 | 確認有確認函式、可中止；沒有人能回答時（EOF）預設為拒絕 |

## 判定規則

- **通過率** = ✅ ÷（✅ + ❌），N/A 不列入分母。
- 以下項目列為**上線阻擋項**，任一 ❌ 就不能上線：B3、B4、C1、C2、C3、D1、D3、E2、F2、F5。
- 其餘 ❌ 要寫進待辦，並註明預計何時補上。
