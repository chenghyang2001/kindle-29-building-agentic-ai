# 代理式 AI 的核心特徵與 7 大設計模式

> K29《Building Agentic AI》第 1 章「代理式 AI 是什麼」演練筆記。
> 每個模式都對照到 Claude Code，方便把抽象概念連到每天在用的工具。

---

## 一、代理式 AI 的四個核心特徵

傳統的 LLM 應用是「一問一答」：給輸入、拿輸出、結束。代理式 AI（Agentic AI）則是讓模型**自己決定下一步要做什麼**，直到目標完成。判斷一個系統算不算「代理」，看下面四點：

| 特徵 | 意思 | 跟一般聊天機器人的差別 | 在 Claude Code 裡 |
| --- | --- | --- | --- |
| **自主性（Autonomy）** | 不需要人每一步下指令，自己決定行動順序 | 聊天機器人等你問下一句；代理自己往下走 | 你說「修好這個測試」，它自己讀檔、跑測試、改碼、再跑，不用你逐步指揮 |
| **目標導向（Goal-oriented）** | 以「完成目標」為終點，而不是「回一句話」 | 聊天機器人回完就停；代理檢查目標達成沒 | 它會跑測試確認變綠才回報，而不是改完就說「應該好了」 |
| **工具使用（Tool use）** | 能呼叫外部工具取得資訊或改變世界 | 聊天機器人只能用訓練知識；代理能讀檔、查網、執行指令 | Read / Edit / Bash / Grep / WebSearch / MCP 伺服器 |
| **記憶／回饋迴圈（Memory & feedback loop）** | 把行動結果帶回下一輪推理，並跨回合保留資訊 | 聊天機器人看不到行動後果；代理看得到並調整 | 工具輸出回到 context（短期記憶）；CLAUDE.md、memory 目錄（長期記憶） |

一句話總結：**代理 = LLM + 工具 + 迴圈 + 目標**。少了迴圈就只是「會呼叫函式的聊天機器人」。

## 二、7 大設計模式

### 1. ReAct（Reason + Act，推理與行動交替）

- **定義**：模型反覆執行「想一下（Thought）→ 做一個動作（Action）→ 看結果（Observation）」，直到能給出答案。
- **何時用**：需要邊查邊推理、事先不知道要走幾步的任務，例如除錯、在陌生程式碼中找東西。
- **在 Claude Code 裡**：問「為什麼登入 API 回 500？」→ 它先想「應該看 route handler」→ `Grep "login"` → 讀到檔案發現呼叫了 `db.query` → 再想「看 log」→ `Bash: tail logs/app.log` → 看到連線字串錯誤 → 給出結論。每一次工具呼叫之間的那段文字，就是 Thought。

### 2. Reflection（反思／自我檢討）

- **定義**：產出初稿後，由模型（自己或另一個角色）批判這份產出，再根據批判修正。
- **何時用**：品質比速度重要、而且「好不好」可以被描述出標準的任務，例如寫文件、寫程式、翻譯。
- **在 Claude Code 裡**：寫完一段程式後執行 `/code-review` 或 `/simplify`，讓審查流程挑出問題，再回頭修改；或在 prompt 要求「寫完後自己檢查邊界情況並修正」。

### 3. Tool Use（工具使用）

- **定義**：模型依照工具的名稱、說明與參數 schema，決定何時呼叫哪個工具，並把結果納入回答。
- **何時用**：答案需要模型訓練資料以外的資訊（檔案、資料庫、即時網路），或需要對外產生作用（寫檔、寄信、部署）。
- **在 Claude Code 裡**：內建 Read / Write / Edit / Bash / Glob / Grep；外接 MCP 伺服器，例如接上 GitHub MCP 後說「列出我最近的 PR」，它會自己挑 `list_pull_requests` 呼叫。

### 4. Planning（規劃）

- **定義**：先把大目標拆成有順序的子任務清單，再逐項執行，必要時修改計畫。
- **何時用**：多步驟、多檔案、步驟之間有依賴的任務；一頭栽進去容易做錯方向時。
- **在 Claude Code 裡**：按 Shift+Tab 進入 **Plan 模式**，它只讀不寫，產出實作計畫等你核准；執行時用待辦清單（TodoWrite）逐項打勾，讓你看到進度。

### 5. Multi-Agent（多代理協作）

- **定義**：多個各有專長或各有獨立 context 的代理分工合作，由一個協調者分派與整合結果。
- **何時用**：任務能拆成互不相干、可平行的子任務，或需要不同角色（研究員／實作者／審查者）互相制衡時。
- **在 Claude Code 裡**：主對話用 **Agent 工具**派出 sub-agent，例如同時派 3 個 `Explore` agent 分別搜尋前端、後端、測試目錄，各自回報結論；`.claude/agents/*.md` 可自訂專職角色（code-reviewer、debug-expert）。

### 6. Sequential（循序／管線式流程）

- **定義**：把工作切成固定順序的幾個階段，前一階段的輸出就是下一階段的輸入，流程由人預先設計好。
- **何時用**：步驟固定、可預測、需要可重現結果的流程，例如「產生 → 驗證 → 審查」或 ETL 管線。和 Planning 的差別是：Sequential 的順序是**設計者寫死**的，Planning 的順序是**模型臨場決定**的。
- **在 Claude Code 裡**：寫一個 skill 或 slash command 規定「先跑 lint → 再跑測試 → 全綠才 commit」；或像「code-writer → code-qa → code-reviewer」三個 agent 依序接力，QA 一定要等 writer 寫完才開始。

### 7. Human-in-the-loop（人在迴圈中）

- **定義**：在關鍵決策點暫停，讓人類核准、修正或提供資訊後再繼續。
- **何時用**：動作不可逆或風險高（刪資料、部署、對外發訊息、花錢），或需求本身模糊、需要人拍板時。
- **在 Claude Code 裡**：**權限提示**（執行 Bash 或寫檔前問你允不允許）、Plan 模式的「核准計畫」、`AskUserQuestion` 選擇題、以及 hooks 在 PreToolUse 階段攔下危險指令。

## 三、模式之間的關係

這 7 個模式不是互斥的，實際系統通常是疊加使用：

```
           ┌──────── Human-in-the-loop（在關鍵點把關）────────┐
           │                                                  │
目標 ──► Planning ──► 每個子任務用 ReAct 迴圈執行 ──► Reflection ──► 完成
                          │        ▲                    │
                          ▼        │                    ▼
                      Tool Use（讀檔、跑指令）     不合格就回頭修
                          │
               子任務太多 ──► Multi-Agent 平行分派
               步驟固定   ──► 改用 Sequential 管線
```

Claude Code 一次普通的「幫我加一個功能」就同時用到了：Planning（待辦清單）、ReAct（邊讀邊改）、Tool Use（Edit/Bash）、Reflection（跑測試發現錯再修）、Human-in-the-loop（權限提示）。

## 四、選模式的速查表

| 你的情況 | 先考慮 |
| --- | --- |
| 不知道答案在哪，要邊查邊想 | ReAct |
| 初稿常常不夠好 | Reflection |
| 需要外部資料或要改變外部狀態 | Tool Use |
| 任務大、步驟多、有依賴 | Planning |
| 子任務彼此獨立、可平行 | Multi-Agent |
| 流程固定、要可重現 | Sequential |
| 動作不可逆、風險高 | Human-in-the-loop |
